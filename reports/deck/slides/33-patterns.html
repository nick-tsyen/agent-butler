Design Patterns & Takeaways

01 Async-first

asyncio is the threading model throughout; asyncio.gather() enables real parallelism for concurrent tool batches.

02 Pydantic at every boundary

All messages, tool results, tasks, skills, and agent definitions are BaseModel subclasses — validated on entry, serialisable on exit.

03 Layered separation of concerns

Five layers, each with one job; communication is always downward via async generators.

04 Generator-based streaming

API layer, core loop, session controller, and UI communicate via AsyncGenerator — no shared mutable state between layers.

05 Multi-source config hierarchy

User → project → session; later entries override earlier; predictable, composable semantics.

06 Everything is a tool / skill / agent

New capabilities are added by implementing Tool, dropping a .md, or adding a .json; the core is closed to modification, extensions are open.

07 Minimal blast radius

is_concurrency_safe(), is_read_only(), permission modes, sandbox profiles, and max_turns all independently limit the scope of any single operation.

These patterns are the design vocabulary of Easy Agent. When in doubt about where to put new code, ask which pattern applies.
