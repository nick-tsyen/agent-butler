## Slide 2 — What is Agent Harness

- Core idea: failures are infra failures, not model failures
- “Repository is the specification” — if it’s not in the repo, it doesn’t exist
- Harness = everything outside model weights (environment, intent, feedback)
- Visual: Simple 3-part stack (Model ↔ Harness ↔ Repo)
- Info sources:
  - `references/01 - Why Capable Agent Still Fail.md`
  - `references/02 - What a Harness Actually Is.md`

## Slide 3 — Five-Subsystem Harness Model (Concept)

- Instruction, Tools, Environment, State, Feedback
- Missing any subsystem → incomplete harness
- Visual: Five-subsystem table from `01 - Why Capable Agent Still Fail`
- Info sources:
  - `references/01 - Why Capable Agent Still Fail.md`

## Slide 6 — Entry File Design (Practice)

- Keep entry file 50–200 lines, “map not manual”
- “Reveal on demand” to module docs
- Place critical rules at top/bottom (lost-in-middle)
- Visual: Before/After mini layout (AGENTS.md + docs/ links)

  - `references/01 - Why Capable Agent Still Fail.md`

## Slide 7 — Initialization Phase (Concept)

- Separate initialization from implementation
- Mixed phases → fragile infra + unverified accumulation
- Initialization is its own phase with completion criteria
- Visual: Phase split diagram (Init → Build)
- Info sources:
  - `references/06 - Make the Agent Initialize Before Every Work Session.md`

## Slide 8 — Initialization Deliverables (Practice)

- Five artifacts: runnable env, test framework, READY checklist, task breakdown, clean git checkpoint
- Four-condition rule (can start/test/see progress/pick up next steps)
- Visual: READY.md checklist snippet
- Info sources:
  - `references/06 - Make the Agent Initialize Before Every Work Session.md`

## Slide 9 — Task Boundaries & WIP=1 (Concept)

- Overreach/under-finish caused by vague scope
- WIP=1 enforced by harness, not agent
- Completion evidence required per task
- Visual: Mermaid flow (feature queue → verify → commit) from `07`
- Info sources:
  - `references/07 - Draw Clear Task Boundaries for Agents.md`

## Slide 10 — Feature List as Harness Primitive (Practice)

- Feature list is machine-readable single source of truth
- Triple structure: behavior + verification + state
- State transitions controlled by harness (pass-state gating)
- Visual: JSON snippet + mermaid state machine from `08`
- Info sources:
  - `references/08 - Use Feature Lists to Constrain What the Agent Does.md`

## Slide 11 — Prevent Premature Victory (Concept)

- ⚠️ Modern models are overconfident (Guo et al.)
- Externalize “Definition of Done”
- Three-layer termination validation (static → runtime → system)
- Visual: Mermaid 3-layer gate from `09`
- Info sources:
  - `references/09 - Preventing Agents from Declaring Victory Too Early.md`

## Slide 12 — Full Pipeline or It Didn’t Happen (Practice)

- Unit tests ≠ completion for cross-component changes
- E2E required for integration tasks
- Architectural boundaries must be executable checks
- Visual: Mermaid E2E pipeline block from `10`
- Info sources:
  - `references/10 - Only a Full Pipeline Run Counts as Real Verification.md`

## Slide 13 — Observability is a Harness Responsibility (Concept)

- Runtime + process observability (what happened / why accepted)
- Without observability: blind retries, subjective evaluation
- Visual: Two-layer observability table from `11`
- Info sources:
  - `references/11 - Making the Agent's Runtime Observable.md`

## Slide 14 — Sprint Contracts & Rubrics (Practice)

- Sprint contract: scope, verification, exclusions
- Structured rubric w/ evidence-based feedback
- OpenTelemetry mapping: session trace → task span → verification sub-span
- Visual: Mermaid contract→execution→rubric loop from `11`
- Info sources:
  - `references/11 - Making the Agent's Runtime Observable.md`

## Slide 15 — Session Continuity (Concept)

- Treat agent like shift engineer with wiped memory
- Clock-in/clock-out routines
- Context anxiety near 60% window
- Visual: Mermaid state persistence flow from `05`
- Info sources:
  - `references/05 - Keeping Context Alive Across Sessions.md`

## Slide 16 — Handoff Artifacts (Practice)

- PROGRESS.md required fields (commit hash, tests, status, next steps)

  - `references/05 - Keeping Context Alive Across Sessions.md`

## Slide 17 — Clean Exit Checklist (Concept)

- 5-dimension exit checklist: build, tests, progress, artifact hygiene, startup path
